# Research workflow

- Before starting any new Edge research, read `docs/edge-research-ledger.md` and search it for the same mechanism, data source, and parameter family.
- Do not repeat a `REJECTED` Edge unless the new run changes the data contract, economic mechanism, or execution assumption in a material way; record that difference explicitly.
- After each completed research wave, update `docs/edge-research-ledger.md` with the hypothesis, data, trial count, verdict, evidence artifact, and condition for revisiting it.
- Keep detailed findings in a dated `docs/edge-search-YYYY-MM-DD.md` note and commit the research record separately from implementation changes when practical.
- Treat 2026 historical data as stress history, not a pristine holdout. Promotion requires a predeclared future shadow-validation window.
